# 命令参数总览

`setup.sh` 与清单工具（`scripts/assemble-manifest.js`）的全部参数。

## 一、命令参数（`setup.sh`）

| 参数 | 取值 | 作用 |
|---|---|---|
| `--to` | `<清单路径>` | 指定项目的 `assemble.json`，后续操作都以它为准 |
| `--check` | 无 | 一致性检查：比对清单两端，报不一致 / 缺失 |
| `--untracked` | 无 | 扫描清单所在目录整棵树，列出不在清单里的文件（按 `.gitignore` 排除） |
| `--pull` | 无 | 回流预演：列出项目侧被改过的素材 |
| `--write` | 无 | 配合 `--pull` 真正写回模板（写前备份） |
| `--migrate` | `<旧清单路径>` | 迁移：以旧清单看现状、新清单看目标，按新结构搬文件并自动改引用 |
| `--dry-run` | 无 | 配合 `--migrate` 只预演不改盘 |
| `--list` | 无 | 列出可用风格素材目录 |
| `-h` / `--help` | 无 | 输出帮助 |

### 典型组合

```bash
./setup.sh --to <清单>                      # 组装
./setup.sh --to <清单> --check              # 一致性检查
./setup.sh --to <清单> --untracked          # 清单外扫描
./setup.sh --to <清单> --pull               # 回流预演
./setup.sh --to <清单> --pull --write       # 回流写入
./setup.sh --migrate <旧清单> --to <新清单> --dry-run   # 迁移预演
./setup.sh --migrate <旧清单> --to <新清单>             # 迁移执行
./setup.sh --list                           # 列风格
```

## 二、清单工具参数（`assemble-manifest.js`）

| 子命令 | 位置参数 | 选项 | 作用 |
|---|---|---|---|
| `validate` | `<清单>` | — | 校验清单结构合法性 |
| `check` | `<清单> <项目根> [<素材基准>]` | — | 清单两端一致性比对 |
| `list` | `<清单>` | — | 列出清单条目 |
| `brand` | `<清单> <输出路径>` | — | 按清单导出品牌信息 |
| `resolve-base` | `<清单>` | — | 解析素材基准目录 |
| `asset-roots` | `<清单>` | — | 列出素材根目录 |
| `init-flag` | `<清单>` | — | 初始化标记 |
| `pull` | `<清单> <项目根> <模板基准>` | `--write` | 素材回流（带 `--write` 才真写） |
| `migrate` | `<旧清单> <新清单>` | `--dry-run`<br>`--write`<br>`--proj-root=<目录>` | 结构迁移并改写引用 |
| `untracked` | `<清单> [项目根]` | `--json` | 清单外文件扫描 |

## 三、参数语义要点

### 默认值方向相反的两处

易混，按上表对应用例操作即可：

| 参数 | 工具层默认 | 脚本层默认 |
|---|---|---|
| `migrate` | **预演**（安全侧），需 `--write` 才动盘 | **执行**，需 `--dry-run` 才预演 |
| `pull` | **预演**，需 `--write` 才写回 | 同工具层，需 `--pull --write` |

设计理由：工具层保守（避免被直接调用时误改），脚本层贴合日常（迁移是常规操作，不该每次额外加参数）。

### 退出码约定

| 命令 | 退出码 0 | 退出码 1 |
|---|---|---|
| `check` | 两端一致 | 有不一致或缺失 |
| `untracked` | 无清单外文件 | 存在清单外文件 |
| `migrate` | 成功 | 失败 |

`check` 与 `untracked` 的退出码 1 是**正常结果而非故障**，可直接挂 CI 作判据。

### 扫描范围差异

| 命令 | 扫描范围 | 忽略规则 |
|---|---|---|
| `check` | 清单目标涉及的顶层目录 | 不适用（只比对清单两端） |
| `untracked` | 清单所在目录**整棵树** | 复用 `.gitignore`（调 `git check-ignore`） |

### 无 git 环境下的降级

`untracked` 在无 git、非仓库或无 `.gitignore` 时，降级为「不忽略任何文件」并在输出中明确提示，不静默改变语义。

> `git check-ignore` 的退出码 0 表示「至少一个被忽略」、1 表示「全都没被忽略」——**1 是正常结果**，仅 128 等才视为失败。
