## 1. 模板分层与素材树

素材全部在仓库根的 `templates/` 下，按**通用程度**分层，内部再按类型（`styles/html/js/json/assets/test`）分目录：

| 层级 | 位置 | 含义 |
|---|---|---|
| 最通用层 | `templates/styles\|html\|js\|json\|assets/` | 所有项目共用，可为空 |
| 系级 | `templates/_downloader/`、`templates/_gallery/` | 下载器系 / 画廊系通用件 |
| 项目独有 | `templates/_downloader/_iwara/`、`_gamebanana-mods/`、`_ktoolbox/` | 单项目专用件 |

- **用哪套由清单决定**，脚本没有「风格参数」：把要的条目都写进同一份 `assemble.json` 即可混搭，同名目标「靠后的源覆盖靠前的」。
- **通用级别是动态的**：项目独有件被复用后，把通用部分上提系级/根级，改清单 src 后用 `--check` 验证。
- **引用按产物位置写**：素材内部的 `require()` / `<script src>` / `@frag:` 都相对**组装后的落点**书写，不相对素材自身位置。所以搬动素材目录只改清单 src、不改 dst，引用不用跟着改。
- 通用运行支撑件在 `lib/`（`cjs-bootstrap.cjs` / `start.sh` / `preview/`），由清单下发到项目。
- 新增系只需在 `templates/` 下建 `_<名>/` 目录（含类型子目录）——`setup.sh --list` 与错误提示会自动发现它，脚本无需改动。

**后端业务 JS 不在模板**：通用件在 `templates/js/`（core/route/http/store/update…），业务实现由各项目自己维护；`_gallery` 例外，连 `server/` 一起带。

## 2. 组装系统（setup）

一个入口 `setup.sh`，动作各一个子脚本（`scripts/setup-*.sh`），共享库 `scripts/setup-lib.sh` 提供环境与参数解析。命令全集与用法见 [命令参数总览](命令参数总览.md)。

| 动作 | 说明 |
|---|---|
| 组装（缺省） | 按清单逐项复制：`src → dst`，以 `/` 结尾表示整目录拷贝；逐文件 `cp -f` 保证「多源写同一目标时后写覆盖」 |
| `--dry-run` | 只列将写入的文件并标注「新增 / 覆盖 / 相同」，不写盘 |
| `--check` | 只比对清单两端（不一致 / 缺失 / 无引用），不组装；不扫清单外文件 |
| `--untracked` | 扫清单所在目录整棵树，列出不在清单里的文件（按 `.gitignore` 排除） |
| `--migrate` | 按落点**文件名**配对搬文件并改写相对引用（结构重排用），`--dry-run` 预览 |
| `--pull [--write]` | 素材回流：把项目侧改过的**素材**写回模板（缺省只预演，`--write` 才写且写前备份） |
| `--fix-perm` | 按 git 索引恢复工作区丢失的可执行位（跨挂载点搬运/解包后执行位会丢） |
| `--list` / `-h` / `--help` | 帮助与素材目录列表 |

**核心约定**：

- **清单即唯一真相**：清单里每条写明「来源 → 落点」，落点一律按清单 **dst**——清单没声明的地方，项目里就不该有文件。
- **清单所在目录 = 项目根**：清单里的相对路径都相对它解析，所以只需给清单路径一个参数。
- **没有 `--to` 就报错**（不静默组装内置清单）；交互式可回答 `y` 生成空白清单骨架，非交互给出 `cp example/assemble.json` 提示。
- **未知参数、多余位置参数直接报错**（不静默吞掉）。
- **分发前预检**：正式组装前会跑一遍 `--check` 同款比对，亮出「将被覆盖的项目改动」与「将补下发的缺失」，只看不阻断（`SETUP_SKIP_PRECHECK=1` 可跳过）。
- **清单 `commands` 钩子**：清单可声明 `"commands": [...]`，组装完成后在**项目根**逐条执行（注入 `SETUP_TEMPLATE_ROOT` / `SETUP_PROJECT_ROOT`），用于生成下游产物（如油猴脚本）；`--dry-run` 只打印，任一命令失败则本次组装非 0 退出。
- **脚本调用一律用 `bash`**（脚本之间、测试内部），不依赖执行位——见第 10 节。

## 3. 清单规范（assemble.json）

顶层只保留实际生效的段：`files` 与 `brand`（`commands` 可选）。JSON 不支持注释，字段含义记在文档里，清单不塞 `_comment`（解析器仍兼容 `files` 内 `_` 开头的键，但新清单不要用）。

```json
{
  "files": {
    "templates/_downloader/html/login.html": "server/public/login.html",
    "templates/_downloader/_iwara/styles/row-thumb.css": "server/public/fragments/styles/row-thumb.css"
  },
  "brand": { "title": "My App", "logo": "brand.png", "icon": "favicon.png", "displayTitle": "My<br>App" },
  "commands": ["node \"$SETUP_TEMPLATE_ROOT/scripts/build-userscript.js\" ..."]
}
```

- **键** = 模板仓库内相对路径；**值** = 项目内相对路径（以 `/` 结尾 = 整目录）。
- **整目录 vs 逐文件**：整目录适合「这个目录的件都要」；逐文件适合**风格层覆盖**场景（一眼看出哪个文件覆盖了哪个同名件）。两种可写同一目标目录，靠后的源覆盖靠前的。
- **`brand` 段**：页面标题/logo/icon 用 `@brand:key@`（属性位）或 `<!-- @brand:key -->`（文本位）书写，运行期由 `templates/js/assemble/fragment-assembler` 取值替换——**品牌不导出独立文件**，实现见 `templates/js/config/brand.js` 的 `readBrand(serverDir)`（读项目根清单的 brand 段）。四个键建议写全，缺键时占位符原样留在页面上（便于发现拼写错误）。
- **`app.js` / `config.schema.json` 是普通清单素材**（由 `files` 显式声明 src 下发），组装不做任何蓝图骨架初始化复制。

## 4. 设置面板模板化

设置面板（`templates/*/html/tab-panel/panel-settings.html`）按卡片拆分，通用卡放系级目录，总装骨架用 `@frag` 嵌套引用（与 `auto-update-card` 同模式）：

| 卡片 | 位置 | 说明 |
|---|---|---|
| 修改密码 `pwd.html` | 系级 `_downloader/html/tab-panel/panel-settings/` | 旧密码 + 新密码（已设密码时服务端校验旧密码） |
| 数据备份 `backup.html` | 同上 | 导出/导入用户数据 zip |
| 登录凭证 `cookie.html` | 同上 | textarea 组合文本（兼容 `Cookie=`/`Token=`/`AccessToken=` 多行与单行粘贴），统一 id `cookieInput`/`saveCookieBtn`/`cookieStatus`/`loginCheckBtn`/`loginStatus` |
| 下载路径 / 点赞 / 播放 / 下载后端 / 索引 | 各项目独有层 | 项目细节差异大，不强行参数化 |

- **保存模型统一为「每卡片小保存」**：每张功能卡自带保存按钮，只提交本卡字段（服务端按字段增量更新，不覆盖其它卡）；面板底部保留一个「保存设置」提交全部字段。
- **通用卡共用同一套 DOM id**；服务端 API 字段名各项目保留（如 `gbCookie` / `iwaraCookie`）。
- 装配器支持 `@frag` 递归嵌套，总装文件引用卡片即可，无需改装配器。

## 5. 油猴脚本模板

通用油猴模板在 `templates/userscript/`，项目特化片段在各自项目层（如 `templates/_downloader/_iwara/userscript/`），**按文件名数字前缀统一排序拼接**：

```
10-consts → 20-core → 25-style → 28-ui → 30-panel → 40-account → 50-project
```

- `templates/userscript/cookie-fetch/`：`header.tpl`（元数据模板）+ `20-core.js`（网络/存储/服务器列表/Cookie 采集/复制/写回）+ `25-style.js`（面板 CSS）+ `28-ui.js`（通用 UI 骨架：FAB/Toast/状态）。
- 项目片段：`00-config.json`（版本/站点/域列表等占位符取值）+ `30-panel.js`（面板 DOM 与事件绑定）+ `40-account.js`（账号检测与渲染）+ `50-project.js`（项目钩子 `openPanel` / `buildPanelHtml` / `bindPanelEvents`）。
- **组装器** `scripts/build-userscript.js`：两侧片段按数字前缀拼接；`header.tpl` 占位符（`{{name}}`/`{{match}}`/`{{grant}}`…）与片段内文本占位符（`{{IDP}}`/`{{STORE_PREFIX}}`/`{{SITE_DOMAIN}}`/`{{SRV_KEY}}`…）都从 `00-config.json` 取值，因此 CSS 字符串与 DOM id 前缀也能参数化；自带自检（片段缺失 / 占位符残留 / 疑似硬编码站点与键名）。
- **生成方式写进清单 `commands`**：`setup.sh` 组装时顺带生成 `.user.js`，setup 不硬编码任何项目。
- **端到端测试**：`templates/userscript/test/verify-userscript-panel.cjs`（环境变量参数化，一套测多站点）+ 各项目层同名测试；用 headless chromium + `GM_xmlhttpRequest` 垫片注入真实脚本、伪造目标站点页面，断言面板挂载 / 探测服务端 / 密码提示 / 凭证回传后服务端存活，并输出截图。
- **凭证刷新脚本**：`templates/_downloader/_iwara/test/iwara-login-flow.cjs`——无头浏览器直连 CF 边缘 IP 过挑战并登录，抓 Token/AccessToken/cf_clearance 后回传服务器自验；参数全走环境变量。

## 6. 前端片段化与资源版本化

- **`@frag:` 骨架**：页面 `index.html` / `style.css` 只留骨架与 `@frag:名称` 指令，运行期由 `fragment-assembler` 从片段目录（`server/public/fragments/`）取值拼装；支持递归嵌套（深度上限 8），缺片段时输出可见提示而不是静默空白。
- **自动版本化**：装配 HTML 时给本地 `<script src="*.js">` / `<link href="*.css">` 自动加 `?v=<内容 md5 前 8 位>`——脚本一改 hash 即变、浏览器强制取新版；模板与项目都不用手写 `?v=`。脚本文件纳入 mtime 缓存检测，改动即重拼。
- **品牌占位符**：`@brand:key@` 与 `<!-- @brand:key -->` 由装配器替换（见第 3 节）。
- **刷新机制**：`partial-refresh.js` 等片段由清单按项目下发。

## 7. 自动更新

- `templates/js/update/auto-update.js` 提供 `createAutoUpdate({projectName, defaultRepo, extraExclude, extraChmodScripts})`；**参数在工厂创建时冻结**，故项目侧用独立参数文件（`server/lib/auto-update-params.json`）在 require 之前读取，而不是往 config.json 或 schema 里塞字段。
- 三种模式：`watch`（文件监控）/ `git`（定时 git pull）/ `github`（从 GitHub 拉取，无需 .git）。
- **排除项**：`start*.sh`、`server/setup.sh`、`server/config.json`、运行态索引等不参与自动更新；`server/boot.cjs` **不排除**（它是零依赖启动器、权威源在模板，排除会让进程级异常兜底修复进不到部署端；更新流程是「先落盘校验 → 再重启」，写坏只影响下一轮）。
- 失败退避与间隔治理见 [自动更新间隔与失败退避](20261008-自动更新间隔与失败退避.MD)。

## 9. 工具与测试体系

**自动维护的文档**（改完代码跑一条命令对齐；有测试盯漂移）：

| 产物 | 生成脚本 | 内容 |
|---|---|---|
| `docs/文件树.md` | `scripts/doc-tree.mjs` | 真实目录树 + 每条一句话介绍（映射在 `tree-doc.json`） |
| `docs/函数列表.md` | `scripts/doc-func.mjs` | 扫 `lib/` `scripts/` `test/` 提取函数（名称/行号/行数/签名） |

- 三份产物都是**生成物**：不要手改，会覆盖、也会被判漂移。

**其他工具**：

- `scripts/assemble-manifest.js`：**清单解析唯一实现**（`list`/`check`/`untracked`/`migrate`/`pull`/`validate`/`brand`/`commands`/`resolve-base`/`asset-roots`/`generate` 等子命令），其他脚本一律调它、不另写解析。
- `scripts/lib-node.sh`：**Node 定位唯一实现**（start.sh / 测试共用）。
- `scripts/scan-sh-commands.js` + `test/check-doc-commands.test.sh`：扫 sh 脚本用法注释与外部命令，校验 README / 命令参数总览里写的命令确实存在。
- `example/`：**完整演示项目**（清单 + 组装产物 + 自研代码 + 假数据 + `self-test.sh` 一键跑），clone 即用，也是测试基准。

**测试**：`bash test/run-all.sh` 汇总跑 `test/*.test.sh`（各自独立进程与临时目录），覆盖清单解析、参数契约、组装行为、混搭、文档一致性、自动维护文档漂移、example 全链路。测试一律用相对路径/派生路径，不硬编码绝对路径。

## 10. 跨环境适配（执行位 / noexec）

工作区可能位于 **NFS 挂载且带 `noexec`** 的路径上，表现为：

- `./setup.sh`、`./start.sh` 直接执行报 `Permission denied`，而 `bash setup.sh` 正常（`noexec` 下任何文件都不能被内核直接执行，`chmod +x` 也无效）；
- 跨文件系统搬运（NFS/CIFS、整目录拷贝、解包）会丢执行位，`git status` 出现成片 `mode change 100755 => 100644` 噪音；
- 此时 shell 的 `[ -x file ]`（走 `access(2)`）**恒为假**，判断「有无执行位」必须用 `stat -c '%A'`。

对应做法：

- **脚本之间、测试内部一律 `bash script.sh` 调用**，只有面向用户的文档示例才写 `./script.sh`（且要求该脚本在 git 里记为 100755）。
- 换工作区/挂载点后跑一次 `./setup.sh --fix-perm` 或 `bash setup.sh --fix-perm`，把丢失的执行位一次修回、`mode change` 噪音清零；该命令还会探测目标是否落在 `noexec` 挂载点并提示改用 `bash`。
- 新增「要被执行」的脚本时，创建后立刻 `git update-index --chmod=+x <file>`（工具创建的文件默认 644）。
- 服务端为**零依赖**项目：不建 `package.json`、lock 文件或 `node_modules`；位于 `"type":"module"` 目录树下时，用 `server/boot.cjs` 强制 CJS 加载，而不是写本地 `package.json`。
