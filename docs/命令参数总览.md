# 命令参数总览

`setup.sh`（总入口，内部按动作分发到 `scripts/setup-*.sh`）与清单工具 `scripts/assemble-manifest.js` 的全部参数。

## 一、`setup.sh`

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| `--to` | `<清单路径>` | 指定项目的 `assemble.json`；清单所在目录即项目根 |
| `--check` | 无 | 一致性检查：逐文件比对清单两端，报不一致 / 缺失 |
| `--untracked` | 无 | 扫清单所在目录整棵树，列出不在清单里的文件（按 `.gitignore` 排除） |
| `--pull` | 无 | 素材回流预演：列出项目侧被改过的素材（只处理 `src == dst` 的素材条目） |
| `--write` | 无 | 配合 `--pull` 真正写回模板（写前备份） |
| `--migrate` | `<旧清单路径>` | 结构迁移：旧清单看现状、新清单看目标，搬文件并自动改写引用 |
| `--dry-run` | 无 | 组装：列出将写入的文件并标注「新增 / 覆盖 / 相同」；迁移：只列将搬动的文件 |
| `--fix-perm` | `[<仓库路径>]` | 按 git 索引恢复丢失的可执行位，并探测是否落在 noexec 挂载点 |
| `--list` | 无 | 列出模板自带的素材目录（最通用层 / 系级 / 项目独有），并输出用法 |
| `-h` / `--help` | 无 | 输出帮助（无参数等同于 `--help`） |

### 环境变量

| 变量 | 作用 |
| --- | --- |
| `DRY_VERBOSE=1` | 组装预演时展开「整目录」条目，逐个列出内部文件 |
| `SETUP_SKIP_PRECHECK=1` | 跳过组装前的清单预检（脚本内部或 CI 批量组装时用） |

### 典型组合

```bash
./setup.sh --to <清单>                          # 组装
./setup.sh --to <清单> --dry-run                # 组装预演（新增 / 覆盖 / 相同）
./setup.sh --to <清单> --check                  # 一致性检查
./setup.sh --to <清单> --untracked              # 清单外文件扫描
./setup.sh --to <清单> --pull                   # 回流预演
./setup.sh --to <清单> --pull --write           # 回流写入（写前备份）
./setup.sh --migrate <旧清单> --to <新清单> --dry-run   # 迁移预演
./setup.sh --migrate <旧清单> --to <新清单>             # 迁移执行
./setup.sh --fix-perm [<仓库路径>]               # 修复执行位
./setup.sh --list                               # 列素材目录
```

## 二、清单工具（`assemble-manifest.js`）

| 子命令 | 位置参数 | 选项 | 作用 |
| --- | --- | --- | --- |
| `validate` | `<清单>` | — | 校验清单结构（顶层类型、`files` 值类型、路径安全、注释键） |
| `check` | `<清单> <项目根> [<素材基准>]` | — | 清单两端一致性比对 |
| `list` | `<清单>` | `--check-base=<目录>` | 展开为「源 <TAB> 目标」，供脚本消费 |
| `brand` | `<清单> <输出路径>` | — | 按清单导出 `brand` 段（无该段时退出码 3） |
| `init-flag` | `<清单>` | — | 打印 `1`/`0`（`init` 段，缺省 1） |
| `commands` | `<清单>` | — | 打印 `commands` 段，每行一条（供组装后执行） |
| `generate` | `<输出路径>` | — | 生成空白清单骨架（不覆盖已存在文件） |
| `resolve-base` | `<探测目录>` | — | 解析清单键的源基准目录 |
| `asset-roots` | `<清单>` | — | 列出被引用的素材根（去重、保序） |
| `untracked` | `<清单> [<项目根>]` | `--json` | 清单外文件扫描 |
| `migrate` | `<旧清单> <新清单>` | `--dry-run`<br>`--write`<br>`--proj-root=<目录>` | 结构迁移并改写引用 |
| `pull` | `<清单> <项目根> <模板基准>` | `--write` | 素材回流（带 `--write` 才真写） |

## 三、参数语义要点

### 默认值方向相反的两处

| 参数 | 工具层默认 | 脚本层默认 |
| --- | --- | --- |
| `migrate` | **预演**，需 `--write` 才动盘 | **执行**，需 `--dry-run` 才预演 |
| `pull` | **预演**，需 `--write` 才写回 | 同工具层，需 `--pull --write` |

工具层保守（被直接调用时不会误改），脚本层贴合日常（迁移是常规操作，不必每次额外加参数）。

### 退出码

| 命令 | 0 | 1 |
| --- | --- | --- |
| `check` | 两端一致 | 有不一致或缺失 |
| `untracked` | 无清单外文件 | 存在清单外文件 |
| `migrate` | 成功 | 失败 |

`check` 与 `untracked` 的退出码 1 是**正常结果而非故障**，可直接挂 CI 作判据。

### 扫描范围差异

| 命令 | 扫描范围 | 忽略规则 |
| --- | --- | --- |
| `check` | 清单目标涉及的顶层目录 | 不适用（只比对清单两端） |
| `untracked` | 清单所在目录整棵树 | 复用 `.gitignore`（调 `git check-ignore`） |

无 git、非仓库或无 `.gitignore` 时，`untracked` 降级为「不忽略任何文件」并在输出中提示，不静默改变语义。

> `git check-ignore` 退出码 0 表示「至少一个被忽略」、1 表示「全都没被忽略」——**1 是正常结果**，128 等才视为失败。
