# 自动更新：模式、间隔与失败退避

服务端代码自动升级：开发机推送后，部署实例按配置自动拉取并重启。本文件说明三种模式、间隔与退避规则、配置入口和判读方法。

## 三种模式

| 模式 | 触发方式 | 需要 `.git` | 联网 | 默认间隔 |
| --- | --- | --- | --- | --- |
| `watch` | 监控本机 `server/` 目录的文件变更，防抖后重启 | 否 | 否 | 无（事件驱动） |
| `git` | 按间隔执行 `git pull --ff-only`，有变更才重启 | 是 | 是（远端仓库） | 300 秒 |
| `github` | 按间隔调 GitHub API 比对提交，有新提交才下载覆盖 | 否 | 是 | 3600 秒 |

## 间隔与退避

- 间隔单位为秒，取值范围 `[30, 86400]`；未设置或非法值 → 取该模式默认值。
- 连续失败时实际间隔 = 基础值 × 2^min(连续失败次数, 3)：`1h → 2h → 4h → 8h`，之后维持 8h。
- 任意一次成功 → 连击归零，立即回到基础间隔。
- 重启中跳过的检查**不计失败**；手动「立即检查」不计入连击，也不改变定时节奏。
- 失败连击是内存态，服务重启后归零。

## 怎么配

**面板**（设置页「🔄 自动更新」卡片）：启用开关、模式下拉、间隔输入（30–86400）、保存 / 立即检查 / 立即重启。
保存调用 `POST /api/auto-update/config`，写回 `server/config.json` 并重启监控。

**配置文件**（`server/config.json` 的 `autoUpdate` 段）：

```json
"autoUpdate": {
  "enabled": true,
  "mode": "github",
  "interval": 3600,
  "githubRepo": "owner/repo",
  "githubBranch": "main",
  "githubToken": ""
}
```

- `githubRepo` / `githubBranch` / `githubToken` 只在配置文件里设置：面板不提交、也不许通过接口覆盖（私有仓库才需要 Token）。
- `interval` 只对 `git` 与 `github` 生效；`watch` 不需要间隔。

## 接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/auto-update/status` | GET | 返回 `config`（`githubToken` 脱敏为空串）与 `status`：`enabled`、`mode`、`restarting`、`lastSha`、`lastCommitDate`、`lastUpdatedAt`、`lastCheck` |
| `/api/auto-update/config` | POST | 接受 `{enabled, mode, interval}`，保存后重启监控；`github*` 字段不进不出 |
| `/api/auto-update/check` | POST | 手动检查一次；仅 `github` 模式可用，其它模式返回 400 |
| `/api/auto-update/restart` | POST | 立即重启（2 秒后），不依赖文件变更检测 |

## 怎么判断生效

1. 面板状态行显示「监控中（mode=…）」；`status.enabled=false` 表示未启用或没装上监控。
2. 日志前缀 `[<项目名>/auto-update]`：每次检查、应用更新、重启都会写一行；退避期间写「连续失败 N 次，Xs 后再试」。
3. 状态文件 `.auto-update-state.json`（项目根，不入库）记录已应用的提交与时间。删除它后首次运行**只记基线、不应用更新**——这是有意的，避免刚部署就被覆盖重启。
4. 用 `/api/auto-update/status` 的 `lastSha` 与远端提交对比：一致即闭环；不一致先看时间是否早于推送。

## 已知限制

- 更新是「覆盖 + 新增」，**不删除**远端已不存在的文件：旧版独有文件会残留成孤儿（无引用，通常无害，可手工移入回收站）。
- 排除清单保护运行态与启停入口：`server/config.json`、`start*.sh`、`server/setup.sh`、`json/` 下运行态文件、`.auto-update-state.json`，以及 `@eaDir`、`node_modules`、`dist`、`release`、`cache-index` 等目录和 `*.log`/`*.pid`/`*.bak` 后缀。被排除的文件不随更新变化。
- `server/boot.cjs` **不在排除清单**：它需要随更新下发（进程级异常兜底修复要能到部署端）。更新流程是「先落盘校验 → 再重启」，写坏只影响下一轮。
- 启动期代码（路由/启停脚本）改动需要重启才生效；`watch` 模式改 `public/` 下片段通常只触发前端热更新，不重启。
- 手动检查只支持 `github` 模式；`watch`/`git` 要看本地变更或下一轮定时。

## 排查

1. **一直是「无新版本」** → 先比时间：日志时间早于推送时间说明还没轮到下一轮（间隔见配置），不是故障。
2. **面板值与实际不符** → 面板只保存 `enabled`/`mode`/`interval`；`github*` 以配置文件为准。
3. **更新后行为没变** → 确认 `lastSha` 是否已变、是否需要重启；再看日志是否报拉取/校验失败。
4. **间隔被拉到 8 小时** → 说明连续失败已达 3 次：查网络、仓库权限、Token 有效期；成功一次即恢复基础间隔。
5. **重启后立刻又检查** → 失败连击不跨进程持久化，重启会从基础间隔重新开始，属预期行为。
