## 一、修改目标

- **问题**：模板默认自动更新间隔 `300` 秒（5 分钟），对「定时从 GitHub 拉取」这种模式过于频繁 —— 每小时 12 次、每天 288 次，而绝大多数项目每天推送不超过 3 次，绝大多数检查是白跑。
- **期望效果**：
  1. 新默认间隔 **3600 秒（1 小时）**，属"低频更新服务"档位；
  2. 连续失败时自动**退避**（间隔 ×2），最多回避 3 次（1h → 2h → 4h → 8h，之后维持 8h 直到成功）；
  3. 需要立即生效时有明确入口：**API `POST /api/auto-update/check`** + 前端「🔍 立即检查」按钮（已存在）；
  4. 前端把**三种模式的区别**写清楚（下拉选项内 + 卡片说明）。
- **成功标准**：
  - 面板新建/未设置时默认显示 `3600`；
  - 连续失败 3 次后，实际检查间隔依次为 7200s / 14400s / 28800s，且封顶 28800s；
  - 一次成功后间隔立即回到基础的 3600s；
  - 下拉三项文案能让人**不看文档就知道三者的差别**。

### 3.2 失败退避：设定值 ×2，最多 3 次

**语义**（按用户确认）：

```
基础间隔 B（用户设定，默认 3600）
连续失败 n 次 → 实际间隔 = B × 2^min(n, 3)
  n=1 → 2B      n=2 → 4B      n≥3 → 8B（封顶，维持到成功）
任意一次成功 → n 归零，间隔立即回到 B
```

**实现要点**：`setInterval` 间隔固定，动态退避必须改为 **`setTimeout` 自递归**：

```js
// github 模式（git 模式同样处理）
let failStreak = 0;
let timer = null;
function computeDelayMs() {
  const backoff = Math.min(failStreak, 3);      // 最多回避 3 次
  return baseSec * Math.pow(2, backoff) * 1000;
}
function scheduleNext() {
  clearTimeout(timer);
  timer = setTimeout(runOnce, computeDelayMs());
}
function runOnce() {
  checkGitHubUpdate(cfg);   // 完成后按结果调整 failStreak 并重新排程
}
```

`checkGitHubUpdate` 结束时（`latest`/`updated` → `failStreak = 0`；`error` → `failStreak++`）回调 `scheduleNext()`。

## 四、潜在问题分析

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| `setInterval` → `setTimeout` 递归引入定时器泄漏 | 中 | 中 | `stop()` 里 `clearTimeout(timer)`；复用现有 `watcher/gitInterval/githubInterval` 收尾路径 |
| 手动检查与定时检查并发 | 中 | 中 | 加 in-flight 标记；`restarting` 已有跳过逻辑 |
| 退避把间隔拉到 8h，用户以为"坏了" | 中 | 中 | 前端显示当前有效间隔与失败连击数（状态区） |
| 旧部署实例不跟随新默认 | **高** | 中 | 文档写明；如需统一可走 API（**需用户同意，本次不做**） |
| git 模式默认仍 300，与 github 不一致致困惑 | 中 | 低 | 前端 hint 明确"两者默认不同及原因" |
| 退避逻辑改动 `checkGitHubUpdate` 既有调用点 | 中 | 中 | 保持函数签名不变，仅在其完成回调里调整计数 |

**边界条件**：

1. `interval` 传入 `undefined` / `null` / `0` / 负数 / 非数字 → 回退到模式默认，负数与超大值 clamp 到 `[30, 86400]`；
2. 首个周期就失败（首次立即检查失败）→ 同样计入 `failStreak`，从 2B 开始退避；
3. 服务重启 → `failStreak` 归零（内存态），退避不跨进程持久化（可接受，见后续清单）；
4. `restarting` 期间检查被跳过 → **不计入失败**（避免把正常重启算成失败）；
5. 手动检查与定时检查同时到达 → in-flight 标记，后者直接返回"已在检查中"。
