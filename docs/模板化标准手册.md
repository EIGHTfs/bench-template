# 模板化标准手册

本仓库的约定集：每条写「怎么做」和「怎么判断做对了」。示例与脚本路径都相对仓库根。

## 1. 素材分层

| 层级 | 位置 | 含义 |
| --- | --- | --- |
| 最通用层 | `templates/js`、`templates/json`、`templates/tools`、`templates/userscript` | 所有项目共用 |
| 系级 | `templates/_downloader/`、`templates/_gallery/` | 下载器系 / 画廊系通用件 |
| 项目独有 | `templates/_downloader/_iwara/`、`_gamebanana-mods/`、`_ktoolbox/` | 单项目专用 |

- **用哪套由清单决定**，脚本没有风格参数；跨层混搭就把条目都写进同一份清单，同名目标「靠后的源覆盖靠前的」。
- **通用级别是动态的**：项目独有件被复用后，把通用部分上提到系级/根级，改清单 `src` 后用 `--check` 验证。
- **引用按产物位置写**：素材里的 `require()`、`<script src>`、`@frag:` 都相对**组装后的落点**，不相对素材自身位置；搬素材只改清单 `src`，`dst` 与引用不动。
- 后端业务代码不在模板：通用件在 `templates/js/`，业务实现由各项目维护（`_gallery` 例外，连 `server/` 一起带）。

## 2. 清单（`assemble.json`）

```json
{
  "files": {
    "templates/_downloader/html/login.html": "server/public/login.html",
    "templates/_downloader/html/tab-panel/": "server/public/fragments/tab-panel/"
  },
  "brand": { "title": "My App", "logo": "brand.png", "icon": "favicon.png" },
  "commands": ["node \"$SETUP_TEMPLATE_ROOT/scripts/build-userscript.js\" ..."]
}
```

| 规则 | 说明 |
| --- | --- |
| 键 | 相对**模板根**的素材路径；以 `/` 结尾 = 整目录下发 |
| 值 | 相对**项目根**的落点；以 `/` 结尾 = 整目录落点 |
| 基准 | 清单所在目录就是项目根，只传清单路径一个参数 |
| 整目录 vs 逐文件 | 整目录省事；逐文件适合「风格层覆盖」，一眼看出谁覆盖谁 |
| 注释键 | `_` 开头的键被解析器忽略，可用于阅读性说明（新清单不必写） |
| `brand` | 页面用 `@brand:key@`（属性位）或 `<!-- @brand:key -->`（文本位）取值；运行期由 `templates/js/config/brand.js` 四级兜底取值（`BRAND_*` 环境变量 → 项目根 `.env` → **项目根清单**的 `brand` 段 → 内置默认），不生成中间文件 |
| `commands` | 组装完成后在项目根逐条执行，注入 `SETUP_TEMPLATE_ROOT` / `SETUP_PROJECT_ROOT`；任一失败则本次组装非 0 退出；`--dry-run` 只打印 |

`app.js`、`config.schema.json` 是普通素材：由清单显式声明下发，组装不做任何骨架初始化复制。

## 3. 前端片段与品牌

- 指令：`<!-- @frag:片段名 -->`（HTML）、`/* @frag:片段名 */`（CSS/JS 均可，片段器同一条正则）。
- 片段名不带扩展名（自动补 `.html`），子目录用 `tab-panel/panel-download`；片段根是目标 `public/fragments/`。
- 嵌套支持递归，深度上限 8 层；缺片段时插入可见的缺失注释并回退旧缓存，页面不白屏。
- 热更新：mtime 取「框架文件 + 所有被引用片段 + 相关本地 js」的最大值，任一改动 → 下次请求自动重拼，无需重启。
- 资源版本化：装配时给本地 `<script src>` / `<link href>` 自动加 `?v=<内容 md5 前 8 位>`，模板与项目都不手写版本号。

## 4. 设置面板卡片化

- 每张卡片一个文件，通用卡放系级 `templates/_downloader/html/tab-panel/panel-settings/`，总装骨架用 `@frag` 嵌套引用。
- 现有通用卡：`pwd.html`（修改密码，必须含 `oldPwd`——已设密码后服务端校验旧密码）、`backup.html`（数据备份/恢复）、`cookie.html`（凭证，textarea 组合文本，兼容 `Cookie=`/`Token=`/`AccessToken=`）。
- **每卡片小保存**：每张卡自带保存按钮，只提交本卡字段（服务端按字段增量更新）；面板底部保留一个总保存。
- 通用卡共用 DOM id：`cookieInput` / `saveCookieBtn` / `cookieStatus` / `loginCheckBtn` / `loginStatus`；服务端 API 字段名各项目保留。
- 项目独有卡（下载路径、点赞/播放、下载后端、游戏映射、索引等）留在项目层，不强行参数化。

## 5. 同名 ≠ 重复

判定顺序：先比内容（逐字节或逐行），再比语义；**内容相同才上提，差异属场景设计就保留**。

- 反例：两个项目各有一套 toast，DOM id/class、类型语义、时长、位置、配色、层级、移动端共 11 个维度里 9 个不同，调用点 32 处 —— 合并等于同时改两个产品的界面，不做。
- 反例：`_gallery/styles` 与 `_downloader/styles` 下的同名 CSS（`base`/`style`/`toast`/`topbar`）内容全不相同。
- 上提步骤：改模板（新建系级素材）→ 各项目清单 `src` 改到系级路径 → 重新组装 → `--check` 两端一致 → 逐项目验证页面。

## 6. JS 分片

单文件 `app.js` 改「功能域分片 + 组装期拼接」，约定见 [组件化约定](20261014-JS组件化方案.MD)。三条铁律：只改分片、产物不手改、改完逐字节自证。

## 7. 下发件改动纪律

清单里声明的文件都是**下发件**：改动一律「改模板 → 重新组装」，直接改项目侧会在下次组装时被**静默覆盖**（覆盖后语法仍合法，只有比对产物才发现）。

验证必须落在**组装产物**上：

```bash
grep -n "改过的内容" server/routes/xxx.js      # ① grep 产物，不是 grep 模板
node -e "require('./server/routes/xxx.js')"    # ② 真加载，能发现语法/依赖错误
bash setup.sh --to <项目>/assemble.json --check # ③ 组装后两端一致
```

签名变更（同步→异步、返回结构变化）改完立刻 grep 全部调用方；行为等价性按「输出不变」逐项确认。

## 8. 自维护文档

| 产物 | 刷新 | 检查 |
| --- | --- | --- |
| `docs/文件树.md` | `node scripts/doc-tree.mjs gen --write` 后 `apply` | `node scripts/doc-tree.mjs check` |
| `docs/函数列表.md` | `node scripts/doc-func.mjs apply` | `node scripts/doc-func.mjs check` |

两者都由标记块维护（`dshgp-tree` / `dshgp-functions`），属**生成物**：不要手改，改完源码跑刷新。

## 9. 执行位与 noexec

- 脚本之间、测试内部一律 `bash script.sh` 调用；只有面向用户的文档示例写 `./script.sh`（并要求该脚本在 git 里记为 100755）。
- 换工作区/挂载点后跑一次 `bash setup.sh --fix-perm`：按 git 索引恢复执行位、清掉 `mode change` 噪音，并探测是否落在 noexec 挂载点。
- 新增要执行的脚本：创建后 `git update-index --chmod=+x <file>`（工具创建的文件默认 644）。
- 判断「有无执行位」用 `stat -c '%A'`；noexec 下 `[ -x file ]` 恒为假，会误判。

## 10. 部署端更新核实

`scripts/verify-deploy.mjs`（零凭据、两阶段）：

```bash
node scripts/verify-deploy.mjs --emit --local <本地仓库> --remote <部署目录> > rc.sh   # ① 生成远端命令
bash rc.sh > deploy-check.txt                                                          # ② 部署端执行
node scripts/verify-deploy.mjs --check --local <本地仓库> deploy-check.txt              # ③ 比对（0=一致）
```

判据：清单内文件**逐个 md5 一致**（证逐字节落地），且部署端 `.auto-update-state.json` 的 `lastSha` 等于本地 HEAD。
判读：先比时间——日志早于推送时间说明还没轮到下一轮；部署端不是 git 目录，`git rev-parse` 不适用；启动期代码改动需重启。

## 11. 门禁命令

| 场景 | 命令 |
| --- | --- |
| 全量测试 | `bash test/run-all.sh` |
| 清单结构 | `node scripts/assemble-manifest.js validate <清单>` |
| 清单两端一致 | `bash setup.sh --to <清单> --check` |
| 清单外文件 | `bash setup.sh --to <清单> --untracked` |
| JS 分片一致 | `node scripts/join-js-parts.mjs <清单> <产物> --check` |
| 渲染点基线 | `node scripts/extract-render-points.mjs --check` |
| 性能反模式 | `node scripts/check-perf-antipatterns.mjs` |
| 文件树/函数列表漂移 | `node scripts/doc-tree.mjs check`、`node scripts/doc-func.mjs check` |
| 部署端一致 | `node scripts/verify-deploy.mjs --check ...` |
